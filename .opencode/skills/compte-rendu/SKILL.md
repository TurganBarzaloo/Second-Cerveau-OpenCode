# Compte rendu

Utiliser pour structurer des notes ou une conversation en compte rendu. Lire uniquement les éléments fournis et les sources nécessaires. Distinguer la date de la réunion, la date du compte rendu et les dates réelles d'exécution ; noter « non précisée » quand elles manquent.

Présenter, selon les informations disponibles, les faits observés et leurs références, les décisions explicitement prises, les actions acceptées avec responsable et échéance seulement s'ils sont indiqués, les idées proposées, les questions ouvertes et les éventuelles simulations. Marquer les inférences ; ne pas inventer de décision, de responsable, d'échéance ni de tâche.

Un simple compte rendu est rendu dans la conversation. Si l'utilisateur demande un fichier, utiliser le répertoire et le niveau de classification appropriés après vérification ; tracer l'écriture selon `AGENTS.md`. Pour modifier une fiche projet à partir de la séance, appliquer `/clore` : présenter les effets précis et attendre sa validation avant l'écriture. Ne pas créer un second état d'avancement.
